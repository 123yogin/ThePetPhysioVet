# SEO implementation

Everything here is **generated from data**. The site content is placeholder demo data
and will be replaced wholesale, so no title, description, canonical, schema block,
sitemap entry or route is hardcoded anywhere.

## Swapping in real data

Edit **two files**, then build. Nothing in the SEO layer needs to change.

| File | What it holds |
|---|---|
| `src/seo/siteConfig.ts` | Business identity: brand, origin, NAP, geo, hours, socials, verification tokens, indexability |
| `src/data/clinicData.ts` | Content: conditions, treatments, clinicians, FAQs, stories, gallery |

```bash
npm run build       # client build → SSR build → prerender + robots/sitemap/llms
npm run seo:check   # regression guard; exits non-zero on failure
```

Adding a condition to `clinicData.ts` automatically produces its route, page,
`<title>`, description, canonical, Open Graph tags, `MedicalCondition` schema,
prerendered HTML file, sitemap entry and `llms.txt` line. There is no second list
to keep in sync.

### Before going live
`npm run seo:check` warns about every unswapped value. The ones that matter most:

1. **`SITE.origin`** — every canonical, `og:url` and sitemap `<loc>` is built from it.
   Wrong origin = every canonical points at the wrong domain.
2. **NAP** (`SITE.address`, `SITE.contact`) — rendered as visible text *and* as
   `PostalAddress` schema from the same source, so they can't drift.
3. **`SITE.geo`** — real lat/long, not the placeholder.
4. **`SITE.sameAs`** — real, claimed profiles only. This is how the brand resolves as
   an entity rather than a string. A dead URL here is worse than an empty array.
5. **`SITE.images.logo` / `ogImage`** — 1200×630 for the OG image.
6. **`SITE.verification`** — Google Search Console and **Bing Webmaster Tools** tokens.
7. **`SITE.indexable`** — set `false` on staging. It emits a site-wide `noindex` *and*
   a blocking `robots.txt`. Never ship `false` to production; `seo:check` fails if a
   production route is noindex.

## What was implemented

### 1. Prerendering — the fix that mattered most
The app was a pure client-side SPA serving an empty `<div id="root">`. Googlebot
renders JavaScript, but in a deferred, rate-limited, failure-prone second pass —
and the AI crawler tier largely **does not execute JavaScript at all** (an analysis
of 500M+ GPTBot fetches found no evidence of JS execution). An HTML-only fetcher
saw a blank page: no conditions, no treatments, no clinicians, no address.

`scripts/prerender.mjs` now renders every route in the registry to static HTML at
build time. `src/main.tsx` hydrates that markup instead of discarding it.

```bash
# The test that matters — content in the first byte, no JS required:
curl -s https://example.com/conditions/ivdd | grep "Intervertebral Disc Disease"
```

This is **not cloaking**: crawlers and users receive the same content, generated by
the same components from the same data. Only the delivery differs.

### 2. Real URLs and crawlable links
Conditions, treatments and clinicians were modal-only state — no URLs, so nothing
was linkable, rankable or citable. Each is now a real route with its own page:

- `/conditions/:id` · `/treatments/:id` · `/team/:id`

Cards previously used `<div onClick>`, which is invisible to crawlers — link
discovery follows `href`s, not click handlers. `EntityCardLink` renders a real
`<a href>` to the detail page while a plain left click still opens the fast in-page
modal, and cmd/ctrl-click opens the real page as a user expects. **No existing
interaction was removed.**

Detail pages have their own layout rather than reusing the homepage behind a modal —
rendering the whole homepage for each entity would create a set of near-duplicate
pages differing by one block.

### 3. Metadata (`src/seo/metadata.ts`)
Per-route titles and descriptions with length discipline enforced in code, because
the copy is generated from data that will change:

- titles 50–60 chars, keyword front-loaded, brand suffix dropped if it won't fit
- descriptions 130–160 chars, padded with real context and truncated on word boundaries

`seo:check` fails the build on an over-length or duplicate title/description.

### 4. Structured data (`src/seo/schema.ts`)
One connected `@graph` per page with stable `@id`s, so the business, its pages, its
services and its people resolve as one entity cluster rather than disconnected blobs:

`VeterinaryCare` (+`MedicalBusiness`, `LocalBusiness`) · `Organization` · `WebSite` ·
`WebPage` · `BreadcrumbList` · `Service` · `MedicalCondition` · `Person` · `FAQPage`

Deliberate omissions:
- **No `AggregateRating` / `Review`** — there are no real reviews in the data. Never
  mark up ratings you don't have.
- **`FAQPage` is still emitted** for machine comprehension, but Google removed FAQ
  *rich results* from Search in May 2026 — it no longer produces a SERP accordion.
  Don't treat it as a visibility feature.
- Schema mirrors visible content only. Marking up invisible content is a spam-policy
  violation.

### 5. Local SEO
`NapBlock` renders name, address, phone and hours as **crawlable text** on every
page, from the same config the schema uses. `BookingForm` and `Footer` were
hardcoding their own copies — the page was rendering **two different phone numbers**
— and now read from `siteConfig` too.

### 6. Crawl directives
Generated at build time so they can't go stale:
- **`robots.txt`** — AI *search/citation* crawlers (`OAI-SearchBot`,
  `Claude-SearchBot`, `PerplexityBot`, `Bingbot`, `Applebot`) are explicitly
  allowed; blocking them removes the clinic from the citation pool. *Training*
  crawlers are a separate toggle: `SITE.allowAiTrainingCrawlers`.
- **`sitemap.xml`** — canonical URLs only; no redirects, 4xx or noindex pages.
  `lastmod` is the build date (see limitations). `priority`/`changefreq` are emitted
  for Bing; Google ignores them.
- **`llms.txt`** — generated map of every page. Adoption is ~10% of domains and no
  major engine has confirmed using it for retrieval: a cheap bet, not a strategy.

### 7. Performance (Core Web Vitals)
- **LCP** — hero and detail images `loading="eager"` + `fetchpriority="high"`;
  `preconnect` to the image host and font hosts; prerendered HTML means content is
  in the first response rather than waiting on a JS bundle.
- **CLS** — explicit `width`/`height` on every `<img>`; fonts already `display=swap`.
  `seo:check` warns on any undimensioned image.
- **INP** — no router library added; the whole routing layer is ~120 lines, because
  every client-side kilobyte is INP budget.

### 8. Regression guard (`npm run seo:check`)
The most valuable artefact here isn't an audit — it's the check that makes the
incident impossible next quarter. It fails the build on: an empty rendered page,
a missing/duplicate/over-length title or description, a missing or non-absolute
canonical, a canonical missing from the sitemap, a production route marked noindex,
a site-wide `Disallow: /`, a missing `h1`, invalid JSON-LD, missing Open Graph tags,
an `<img>` with no `alt`, or a sitemap URL with no generated file.

**Wire it into CI.** The failures it catches — a staging `noindex` reaching
production, an empty shell after a build change — are the ones that actually cost
traffic, and they are invisible until the traffic is gone.

## Hosting requirements

The build emits directory-style static pages (`/conditions/ivdd/index.html`).

- **Serve `/path/index.html` for `/path`.** Netlify, Vercel, Cloudflare Pages,
  nginx (`try_files`) and S3+CloudFront all do this with standard static config.
- **Use `dist/404.html` as the 404 document**, and return a real **404 status** —
  not a 200 soft-404, and not an SPA rewrite of everything to `/index.html`. A
  catch-all rewrite would make every URL return the homepage and break the whole
  point of prerendering.
- **Pick one trailing-slash form and 301 the other.** Canonicals are emitted without
  a trailing slash (except `/`).
- `vite preview` is configured to mimic this (see `servePrerendered` in
  `vite.config.ts`), so local verification reflects production.

## Known limitations / next steps

Honest list of what this does **not** do:

1. **`lastmod` is the build date for every URL**, not a real per-page modification
   date. An inaccurate `lastmod` teaches Google to ignore the field. Fix when content
   moves into a CMS.
2. **No author attribution on clinical claims.** Pet-health content is YMYL-adjacent;
   Google's guidance for that territory expects named, credentialed authors and claims
   sourced to named guidelines. The clinician pages and `Person` schema are the
   foundation, but condition pages should carry a visible
   "reviewed by <clinician> on <date>" line and cite veterinary sources.
3. **No reviews.** Review signals are a significant share of local pack weight. This
   needs a real review-collection process before any `AggregateRating` markup — never
   fabricate or gate reviews.
4. **No Google Business Profile.** GBP is the single heaviest local ranking asset and
   lives outside the codebase. Claim it, set the primary category, and mirror the
   treatments in `clinicData.ts` as GBP services.
5. **Images are remote `lh3.googleusercontent.com` URLs** with no responsive `srcset`
   and no AVIF/WebP negotiation. Self-host with `<picture>` + `srcset` for a real LCP win.
6. **No form backend.** The booking form generates a client-side reference ID and
   submits nowhere — a conversion path that doesn't convert.
7. **Single locale.** No `hreflang`; add it only if genuinely serving multiple
   languages or regions, and validate reciprocity if you do.
8. **`priceRange`, `foundingYear`, `areaServed`** are placeholders that appear in
   public schema. Wrong data in structured markup is worse than absent data.
